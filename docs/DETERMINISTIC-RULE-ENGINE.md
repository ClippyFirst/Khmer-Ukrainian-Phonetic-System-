# Детермінований кмерський рушій

Активний браузерний рушій і Python API за замовчуванням працюють за фіксованими правилами. Нейромережі, мережа та сторонні G2P-процеси не запускаються автоматично.

## Конвеєр

1. NFC-нормалізація та сегментація кмерського письма.
2. Структурний розбір приголосних, підрядкових знаків, голосних і регістрових маркерів.
3. Для лексичних винятків — точний пошук у версійованому наборі засвідчених прикладів.
4. Для підтриманих структур — явне правило серії та притаманного голосного.
5. Перевірка IPA → українська за канонічною таблицею.

## Детермінованість і межі

Однаковий нормалізований ввід, версія правил і набір даних дають однаковий результат. Це властивість обчислення, а не доказ фонетичної істинності. Статус PROPOSED залишається запропонованим; непідтримані комбінації повертають NOT_ESTABLISHED або EVIDENCE_LIMITED.

Профіль: khmer-pph-careful-citation-v1. Романізація — окремий режим.

## Python: правиловий рушій

```python
from khmer_ua import RuleBasedKhmerEngine
result = RuleBasedKhmerEngine().analyze("ខ្មែរ")
```

## Дослідницький гібридний API

HybridKhmerEngine обгортає RuleBasedKhmerEngine і за явної конфігурації запускає зовнішні provider-и. MekongPhon має окремий pinned CPU adapter; Goruut, Khmer Phonemizer та Epitran можна підключити через make_command_backend із зафіксованою версією/командою. Кандидати зберігаються з provenance, але ніколи не голосують і не замінюють фінальне IPA автоматично. Без provider-ів результат дорівнює результату правилового рушія.

```python
from khmer_ua import HybridKhmerEngine, make_mekongphon_backend
engine = HybridKhmerEngine({"mekongphon": make_mekongphon_backend()})
result = engine.analyze("ខ្មែរ")
```

Цей шар — дослідницький comparator, а не production fallback. Просування кандидата потребує незалежного gold для профілю Phnom Penh та окремої перевірки тону, довготи, код і сегментації. Див. docs/hybrid-engines.md.
